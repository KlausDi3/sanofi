🏗️ HICode — Full-Stack Architecture
═══════════════════════════════════════════════════════════════════════════

Two services + OpenAI. Frontend posts a job, backend runs the HICode
pipeline asynchronously, frontend polls until done.

─§ Layered view ─────────────────────────────────────────────────────────

+----------------------------------------------------------+

                          ▼
+----------------------------------------------------------+

─§ Backend pipeline (run_hicode_pipeline) ───────────────────────────────

📥 Input          🎯 Filter          🏷️ Label             🌲 Cluster           📤 Result
+----------+    +-------------+    +--------------+    +---------------+    +------------+
| 📂 docs  |───▶| 🔎 embed +  |───▶| 🧠 GPT-4o    |───▶| 🧠 GPT-4o-mini|───▶| 📋 topics  |
| {id:txt} |    | cosine sim  |    | per review   |    | merge labels  |    | + reviews  |
| (or CSV) |    | top-K, ≥τ   |    | "LABEL: ..." |    | iterate ≤3×   |    | + scores   |
+----------+    +-------------+    +--------------+    +---------------+    +------------+
   step 0           step 0              step 1              step 2              step 3
  (skip if no                       label_generation.py  label_clustering.py  build response
   query given)                     generate_labels()    cluster_labels_gpt() (theme→docs map)

─§ Causal arrows ────────────────────────────────────────────────────────

  query  ━━▶ relevance_scores       (filter only when query is non-empty)
  query  ━━▶ system_prompt          (steers labels toward topic of interest)
  labels ━━▶ themes                 (fan-in: many labels → few clusters, repeated)
  themes ━━▶ topic.documents        (reverse-map via label_to_theme[label.lower()])

─§ Request lifecycle ────────────────────────────────────────────────────

   🧑 click           🌐 frontend                  ⚙️ backend                     🤖 OpenAI
   ───────           ─────────────                 ───────────                    ─────────
   "Run"  ────▶  POST /api/analyze
                 (datasource_id|documents,
                  query, coding_goal)

                                   ◀─── status: processing | progress: "..."
                                   ◀─── status: completed  | result: {topics, ...}
   ⬜ → ⏳ → ✅
   show topics

─§ Notable details ──────────────────────────────────────────────────────

  • Job state is in-memory only — restart ⟶ all jobs lost. 🚩 prod gap.
  • Documents are passed by value through the API — large corpora ⟶ big payloads.
  • `_0` segment suffix on doc_id is a sentence-segmentation hook
    (currently every doc is one segment; reverse-mapped before returning).
  • Filter falls back to top-5 if nothing clears the 0.25 cosine threshold.
  • Clustering loops until n_batch ≤ 1 OR max_n_iter (=3); each iter
    re-clusters the *cluster keys* from the previous iter ⟶ hierarchy.
  • CORS allow-list pinned to localhost:3000/3002 + phytopic.jjluo.com.
